# Proposals — backend/src/main/run

## Proposal 1: Log full draft model output on validation failure

- **Target:** `backend/src/main/run/manager.ts:294-295` (`flowA` draft validation) and `backend/src/main/validators/responses.ts:19` (`validateDraft`)
- **Issue:** When `validateDraft` fails (e.g. `invalid_model_response: approval note failed validation at 'sections': draft is missing required grounding content (expected four unique sections and SOP-114 grounding)`), `manager.ts` only throws `validationMessage` with path/message. The full normalized `ModelResponse.result` that the model actually returned (sections, body, citations) is discarded, so the 50KB vision image case — vision succeeded but draft failed mid-way — cannot be diagnosed without reproducing.
- **Evidence:** User report: 50KB image vision worked, then `draft-qwen3` returned invalid draft. Current `flowA` at `manager.ts:294` does `if (!draft.ok) throw new Error(validationMessage("approval note", draft.error))` without persisting `(draftResponse.value as ModelResponse).result`. Gateway now logs full model return (see `backend/src/main/gateway/model-gateway.ts:18`), but manager's validation context is still lost if gateway log is rotated or not correlated.
- **Suggested change:** On `!draft.ok` (and similarly `!vision.ok`, `!code.ok`), persist a validation trace to `data/runs/<runId>/logs/validation-failed-<taskType>-<requestId>.json` via `writeRunFile(runId, "logs", ...)` or `appendFileSync(runRoot(runId)/logs/...)` containing: `requestId`, `taskType`, `validationError` (path/message/expected), `fullResult` (the parsed JSON), `retrievedChunks` (for citation/grounding checks), and `rawText`/`envelope` if available from gateway. Also `console.error` with preview and emit a `tool_result` with `validation-failed` summary.
- **Reason:** Makes SOP-114 grounding failures instantly debuggable: shows whether model omitted `grounding-references` section, duplicated an `id`, or body lacked `SOP-114` string, without needing to re-run the model.
- **Impact:** Small write per failure only; no hot-path cost on success. Complements gateway's `model-gateway.log` — provides correlated validation view. Keep `bodyPreview` truncation in console but full JSON in file.
